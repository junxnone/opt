# 性能优化

## 目的

  - 让程序执行更快(**Latency**)
  - 同一时间内运行更多的任务(**Throughput**)
  - 占用更少的内存(**Memory**)
  - 单位功耗完成更多工作(**Power/能效**)：不是一味追求绝对速度，而是提升 Performance per Watt，和
    Power/Thermal Bound（Issues）、DVFS/Turbo Boost（Hardware Tech）对应
  - 增加核心数/节点数时性能能同比提升(**Scalability**)：而不只是单机下跑得快，和 Scalability 指标（Algo
    Metrics）、Serialization Bound（Issues）对应
  - ...

## 优化层级导航

性能优化的关注点分布在不同层级，自上而下排查效率最高：先确认算法本身是否有更优实现，再看数据布局与并行化是否打满硬件能力，最后用
profiler 定位具体卡在哪个硬件微架构环节。

## 相关名词

  - **Front End**: 从内存中拉取指令并将指令翻译为微操作（micro-operations, μops），这些 μops
    会被传递给后端部分，但通常这些 μops 会暂存在 ready-μops-queue 中。
  - **Back End**: 以原始程序中的顺序调度（schedule）、执行（execute）和提交（commit, retire）这些
    μops
  - **Stall**: 阻塞, CPU 等待数据, 未工作(资源竞争/数据读写)
  - **IPC**: `Instructions per cycle` 每时钟周期运行的指令数，数值越高说明流水线利用越充分，VTune
    里对应指标的具体解读见 [Vtune Metrics](0056_Tools_Vtune_Metrics)
  - **CPI**: `Cycles per Instruction` 每条指令的平均时钟周期数，是 IPC 的倒数视角，同样详见
    [Vtune Metrics](0056_Tools_Vtune_Metrics)
  - **主频**: CPU 运行频率
  - **时钟周期**: 时钟频率倒数
  - **机器周期** - CPU 周期: 基本操作/元操作 周期(从内存里面读取一条指令的最短时间)
  - **指令周期**: 取出一条指令并执行这条指令的时间
  - **MIPS** - `Million Instructions Per Second` : 每秒执行百万条指令数
  - **MFLOPS**- `Million Floating-point Operations per Second`:
    每秒百万浮点数运算
  - **PMUs**: CPU 内核中的专用逻辑块，用于记录计算系统上发生的特定硬件事件(缓存遗漏/分支错误预测),
    这些事件组合起来创建有用的高级指标，如 CPI 。PMU
    硬件计数器溢出触发采样的具体原理见 [Vtune
    HWE](0053_Tools_Vtune_HWE)

## Issues

  - Front-End Bound：前端取指/译码跟不上后端消费速度，TMA 四大类之一，见 [TMA](0047_OPT_TMA)
  - Bad Speculation：分支预测错误/机器清空（machine clear）浪费的流水线资源，TMA 四大类之一，见
    [TMA](0047_OPT_TMA)
  - Memory Bound：性能受限于内存子系统（带宽、延迟、cache 命中率），是 TMA 方法论里 Back-End Bound
    的主要子类，方法论细节见 [TMA](0047_OPT_TMA)，VTune 下的具体分析见 [Vtune Memory
    Access](0059_Tools_Vtune_AT_MA)
  - Compute Bound：性能受限于计算资源本身（执行单元吞吐、长延迟运算链、指令依赖），对应 TMA 里的 Core Bound /
    Retiring，见 [TMA](0047_OPT_TMA)
  - Latency Bound vs Bandwidth Bound：Memory Bound
    的两种不同成因——前者受限于单次访存的延迟，后者受限于访存带宽上限，优化方向也不同（前者靠预取/提高访存并行度，后者靠减少总访存量、改善数据局部性），细分指标见
    [Vtune Metrics](0056_Tools_Vtune_Metrics)
  - Synchronization/Lock Bound：多线程间因锁、barrier 等同步原语产生的等待开销
  - I/O Bound：受限于磁盘/网络的吞吐或延迟，而非 CPU 本身计算能力
  - NUMA Bound：跨 Socket 访问远程内存/缓存带来的额外延迟，常见于多路服务器
  - Serialization Bound：并行化不充分、串行部分占比过高限制了整体加速比，理论基础见
    [并行计算理论](0012_PARA_Theory)
  - Power/Thermal Bound：因功耗/温度限制触发降频（Turbo Boost 回落），实际运行频率低于预期

## Hardware Tech

  - Prefetch（预取）：在数据真正被使用前提前将其搬入 cache，用来掩盖访存延迟；分硬件自动预取和软件显式预取（编译器
    intrinsic/指令）两种
  - Predication（谓词执行）：用条件执行/select
    指令替代分支跳转，避免因分支预测失败而导致的流水线清空开销，代价是两个分支都会被执行
  - Out-of-Order Execution（乱序执行）：CPU
    不按程序顺序、而按操作数就绪情况调度指令执行，用来填充因等待数据而产生的流水线气泡，是现代超标量
    CPU 隐藏延迟的核心手段
  - Pipelining（流水线）：将指令执行拆分为取指/译码/执行/访存/写回等多个阶段，不同指令的不同阶段可以重叠执行，提高吞吐
  - Superscalar（超标量/多发射）：每个时钟周期可同时取指、译码、派发多条指令到不同执行端口，是 IPC 理论上限大于 1
    的硬件基础
  - Branch Prediction（分支预测）：提前预测分支走向并推测执行后续指令，预测错误时触发机器清空（对应 Bad
    Speculation）；和 Predication 是解决分支问题的两种不同思路——预测 vs 直接消除分支
  - SMT /
    Hyper-Threading（同时多线程）：单个物理核同时运行多个逻辑线程，共享执行单元填补流水线气泡，提高核心利用率但不增加物理计算资源
  - Cache Hierarchy（多级缓存）：L1/L2/L3 逐级增大、增慢、共享范围增广的缓存层级，用来弥合核心计算速度与 DRAM
    访问延迟之间的差距
  - DVFS / Turbo
    Boost（动态调压调频）：根据负载、功耗、温度约束动态调整频率/电压，短时突发负载可睿频到更高频率，持续高负载或多核满载时会回落降频
  - Huge Pages（大页）：使用更大的页大小（2MB/1GB）减少页表项数量，从而降低 TLB miss 率，常用于大内存占用的应用

## Algo Metrics

  - 时间复杂度：算法执行时间随输入规模增长的渐进增长趋势（如 O(n)、O(n log n)）
  - 空间复杂度：算法占用内存随输入规模增长的渐进增长趋势
  - Arithmetic
    Intensity（计算强度）：单位访存字节对应的浮点运算次数（FLOPs/Byte），决定了算法在给定硬件上理论是
    Compute Bound 还是 Memory Bound，是 Roofline Model 的核心指标（见下文）
  - Work / Span：并行算法复杂度的两个基本量——Work（单核执行总操作数）与 Span（关键路径长度），二者之比
    Work/Span 即理论最大并行度
  - Scalability（扩展性）：Strong Scaling（固定总问题规模、增加核心数看加速比）vs Weak
    Scaling（随核心数等比例增大问题规模、看吞吐是否线性增长），理论基础见
    [并行计算理论](0012_PARA_Theory)

## Roofline Model

Roofline Model 把一个 kernel 的 **Arithmetic
Intensity**（横轴，FLOPs/Byte）和**实际达到的性能**（纵轴，FLOPs/s）画在同一张图上，用两条线确定理论性能上限：

  - 水平线：硬件峰值算力（Peak FLOPs/s），由核心数 × 向量宽度 × 频率决定
  - 斜线：峰值内存带宽 × Arithmetic Intensity

一个 kernel 的 Arithmetic Intensity 落在斜线左侧（低于拐点）就是 **Memory
Bound**，应优先优化数据局部性、减少访存量；落在斜线右侧（高于拐点）就是 **Compute
Bound**，应优先优化向量化、减少指令数——这正好和上面 Issues 里的 Memory Bound / Compute Bound
一一对应，把"该往哪个方向优化"从经验判断变成了可计算问题。[Intel Advisor](0008_Tools_Advisor)
的 Roofline 分析功能可以直接画出这张图并标出每个 kernel 的位置。

## 优化方法论

典型的性能优化是一个迭代环，而不是一次性动作：

1.  **建立基线（Baseline）**：先测出当前性能数值，作为后续优化效果的对照
2.  **Profile 定位瓶颈**：用 [Intel Vtune](0006_Tools_Vtune) 等工具跑一遍，确定瓶颈落在
    Issues 里的哪一类（Front-End Bound / Bad Speculation / Memory Bound /
    Compute Bound / ...）
3.  **针对性优化**：根据瓶颈类型选择对应的 Hardware Tech、数据布局或并行化手段
4.  **验证回归**：重新测量，确认优化生效且没有引入新的瓶颈或正确性问题，然后回到第 2 步
